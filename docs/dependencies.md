# Casa Velado — зависимости и оправдания

Вътрешен документ (български). Blueprint-ът изисква писмено оправдание за всяка зависимост. Оправданията стоят тук, а не в `casa-velado-blueprint.md`, защото blueprint-ът не се променя без изрично одобрение.

## Runtime (формират сайта)

| Пакет          | Защо                                                                                                                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `astro` ^7.3.5 | Заключен стек (10.1). Статично генериране, вградена обработка на изображения, колекции. Не се ползва `ClientRouter`, няма prefetch. Тегли `sharp` като опционална зависимост, нужна за WebP конвертирането. |

Към клиента не се изпраща JavaScript от никоя зависимост. Съдържателните страници имат бюджет < 20KB gzip собствен код (9.1).

## Само за разработка (не се изпращат към клиента)

| Пакет                               | Защо                                                                               |
| ----------------------------------- | ---------------------------------------------------------------------------------- |
| `typescript` ^6.0.3                 | Проверка на типовете. Версия 6, защото `astro check` още не поддържа TypeScript 7. |
| `@astrojs/check`                    | `astro check` за `.astro` и `.ts` файловете. Това е „линтерът“ от етап 1.          |
| `@types/node`                       | Типове за `astro.config.mjs` и `scripts/` (Node API).                              |
| `prettier`, `prettier-plugin-astro` | Форматиране.                                                                       |

ESLint не е добавен. Правилата за достъпност се проверяват с axe и ръчно в етап 16.

## Планирани по-късно (само за разработка, преди добавяне се докладват)

| Пакет           | Етап                         | Защо                                                         |
| --------------- | ---------------------------- | ------------------------------------------------------------ |
| `lighthouse`    | При всеки етап, за бюджетите | Проверка на Performance, Accessibility, Best Practices и SEO |
| `@axe-core/cli` | Етап 16                      | Автоматична проверка за WCAG A/AA                            |

За словесния знак (букви в контури) и подмножествата на шрифтовете ще се ползва еднократен скрипт; ако е нужен пакет, ще се докладва.

## Собствен код вместо пакет

- Sitemap: `src/pages/sitemap.xml.ts` вместо `@astrojs/sitemap`.
- WebP само: `src/lib/webp-image-service.mjs` (обвивка около вградената услуга на Astro).
- Шрифтове: локални WOFF2 файлове, без `@fontsource`.

## Етап 3

Нови зависимости няма. За генерирането на марката (`scripts/brand/build-brand.mjs`, ръчно, извън билда):

- `fontkit` се инсталира с `npm i --no-save` и не влиза в `package.json`. Чете контурите на буквите.
- `svgo` и `sharp` идват с Astro и се ползват от скрипта. `sharp` рендира PNG за `apple-touch-icon.png` и за записите в `favicon.ico`.

## Етап 6

Нови зависимости няма. Компонентите са собствен код (Astro + CSS). Единственият нов клиентски скрипт е плавното показване на снимка (≈ 0,1 KB gzip в `shell.ts`). В `astro.config.mjs` има малка собствена интеграция, която след билда маха ненужните растерни първообрази от `dist/_astro`.

## Етап 7

Нови зависимости няма. Страницата има един собствен скрипт (9,3 KB, 3,6 KB gzip), зареден само на `/cigars`.
